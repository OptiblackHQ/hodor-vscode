# Hodor for VS Code and Cursor

Your product's tracking plan from [Hodor](https://hodor.optiblack.com), inside your editor.

- **Events by status:** Not started, Ready to implement, In progress and Implemented, with search.
- **Event details:** description, platforms, and every property with its type and sample value.
- **Copy code:** the event's tracking function in any of the product's languages, or the whole tracking file. The code is generated by Hodor, the same code the website and `npx @optiblack/hodor` give you.
- **Set status:** mark events in progress or implemented, and the product team sees it in Hodor.
- **AI coding agent (chat):**
  - Ask about the plan ("how many events are not implemented?").
  - Say "implement them": it finds where each event happens in your code, adds Hodor's tracking code there, and marks the event implemented.
  - Paste events from a sheet or ticket and say "implement these": it adds them to your code too.
  - Any other coding task: explain code, fix errors, write features. It can run commands (install, build, test) after you click **Run**.
  - Paste screenshots (errors, dashboards, plan tables) into the chat.
  - Works across several repos at once.
  - Uses your own Claude or Google Gemini key (a free Gemini key works), added once in Hodor.

## Sign in

1. Open the Hodor icon in the activity bar and click **Sign in to Hodor**.
2. Your browser opens Hodor. Check that the code matches the one in the editor, choose which products the editor may see, and approve.

**Allow changing event status** is ticked by default, because the extension needs it to update status. Untick it for a read-only sign-in.

The sign-in is a personal Hodor token. It is stored in your operating system's keychain (VS Code Secret Storage), never in settings or files. **Hodor: Sign out** removes it from the editor and revokes it in Hodor. You can also revoke it on Hodor's MCP / CLI page.

## Pick a product

**Pick product** (the project icon in the view's title bar) chooses the product for this workspace, and the choice is remembered.

If the repo was linked with the Hodor CLI (`npx @optiblack/hodor init`), its `.hodor.json` picks the product for you.

## AI chat

Open **Chat** in the Hodor sidebar.

The chat is a coding agent for the open project, with Hodor's tracking plan built in. Ask it anything about the code, or give it any coding task.

**Asking about the plan.** Questions like "what does checkout send?" are answered from Hodor.

**Implementing events.** For "implement the events that are not started", the chat:
1. searches and reads your code to find where each event happens;
2. gets Hodor's generated tracking code in your project's language;
3. proposes small edits;
4. marks each event *implemented* in Hodor once its edit is applied.

It decides where each call goes itself, and its summary says which place it chose and why.

**Events that aren't in Hodor.** Paste them (names and properties, from a sheet or a ticket) and say "implement these". The chat adds them to your code in the style of your existing tracking code, using the names exactly as given. It doesn't change Hodor; its summary lists which events aren't in Hodor's plan.

**The input box.** Type, paste screenshots, then pick:
- **Mode** (what the AI may do without asking):
  - **Plan:** it reads the code and writes a plan, changes nothing. Click **Approve plan** to start.
  - **Ask before edits** (default): every change waits for **Apply**, every command for **Run**.
  - **Edit automatically:** changes apply right away; commands still ask.
  - **Full access:** changes and commands run without asking (it asks you to confirm once). Protected folders and private files stay blocked.
- **Model:** Claude Sonnet, Haiku or Opus, or the Gemini models your key allows. Switch any time; the chat continues with the new model. New chats start on your last pick.

Enter sends, Shift+Enter adds a line; the round button turns into **Stop** while it works. On a Mac, press **Fn** twice to dictate.

**History.** Every chat is saved for this project. **History** lists them; open one to read or continue it, or delete it. Changes proposed in an earlier session can't be applied any more.

**Commands.** It installs packages, builds, runs tests, linters and type checks to check its work, up to 10 minutes each, with live output. It can start a dev server in the background, read its output and stop it. Each command shows with **Run** and **Skip** unless you chose Full access. It also reads the errors and warnings in VS Code's Problems panel.

**Copying.** Code blocks in answers have a **Copy** button, and so does every answer.

**Following along.** Every step shows as it happens; runs of file reads and searches fold into one line you can open. Click a file to open it, and use **View change** to see an edit side by side. Undo and git work as usual.

**Stop, Retry, Continue.**
- **Stop** ends the run, and changes already applied stay.
- If the connection drops, **Continue** picks up where it stopped.
- If Claude is busy, **Retry** sends the same request again.

**What the AI can and can't touch:**
- **Reads:** only files inside the open project folder. It never sees `.env` files, keys and certificates, `node_modules`, build folders, or anything your `.gitignore` hides.
- **Changes:** it can't delete files. An edit is refused if the file changed after the AI read it.
- **Commands:** only the ones you click **Run** on (or all, in Full access). They run in the project folder with your permissions, so read each one first.

**Screenshots.** Paste one (⌘V / Ctrl+V), drop it on the message box, or click **+ Image**; up to 4 per message. They are shrunk before sending. A chat holds a limited number of screenshots; start a new chat for more.

**Several repos.** Open a folder that holds your repos (for example `Optiblack/` with `shop/`, `admin/`, `api/` inside), or add each repo to one workspace (**File → Add Folder to Workspace**). The chat sees all of them, knows which language each uses, and runs commands in the right one. Each repo's `.gitignore` is respected.

**AI keys.** Add your own key once on Hodor's **MCP / CLI** page, under **AI keys for the editor chat**. It works for every product and repo you open.
- **Claude** (console.anthropic.com): paid per use, the best results.
- **Google Gemini** (aistudio.google.com): free keys work, with daily limits. Pick the model there; Flash-Lite has the highest free limits.
- Pick the model in the input box. Your spend (Claude in dollars, Gemini in tokens) and an optional monthly Claude budget are on the same Hodor page.
- A product owner can also add a Claude key to a product; people without their own key then use it.
- The extension never sees a key: Hodor's server calls the AI with it. Code the AI reads is sent to Hodor and then to Anthropic or Google under that key. On Google's free plan, Google may use it to improve its models.
- Without a key, the chat says so and everything else keeps working.

## Settings

| Setting | Default | |
|---|---|---|
| `hodor.serverUrl` | `https://hodor.optiblack.com` | Change only to test against a local Hodor. |
| `hodor.ai.mode` | `ask` | `plan`, `ask`, `auto` or `full` (also in the input box). |
| `hodor.ai.model` | | The model (also in the input box). |

## Develop

```bash
npm install
npm run build        # bundle to dist/ (npm run watch while developing; F5 starts an Extension Development Host)
npm test             # unit tests (vitest)
npm run package      # typecheck, build and create hodor-<version>.vsix
```

Integration tests run the extension in a real VS Code against a local Hodor (`npm run dev` in the hodor repo):

```bash
HODOR_URL=http://localhost:3000 HODOR_TOKEN=<write token> HODOR_PROJECT=<product id> npm run test:integration
VSCODE_VERSION=1.85.2 npm run test:integration   # oldest supported VS Code (Cursor is based on an older one)
```

The chat tests also need a Claude key on that product. With `scripts/fake-claude.mjs` from the hodor repo (and Hodor started with `HODOR_ANTHROPIC_BASE_URL` pointing at it), they cost nothing; add `HODOR_PROJECT2`, a product without a key.

Without those variables, only the offline checks run. Signing out at the end revokes the token.

If you run the tests from a terminal inside VS Code or Cursor, unset `ELECTRON_RUN_AS_NODE` first (`env -u ELECTRON_RUN_AS_NODE npm run test:integration`).

## Publishing (one-time setup, then per release)

1. **VS Code Marketplace:** create the `optiblack` publisher at <https://marketplace.visualstudio.com/manage> and an Azure DevOps token with *Marketplace (Manage)* scope. Then run `npx vsce login optiblack` and `npx vsce publish`.
2. **Open VSX (used by Cursor):** create an account at <https://open-vsx.org>, sign the publisher agreement, create the `optiblack` namespace (`npx ovsx create-namespace optiblack -p <token>`), then run `npx ovsx publish hodor-<version>.vsix -p <token>`.

The Hodor server must already have the endpoints this version uses (deploy Hodor first).
